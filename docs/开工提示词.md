# 开工提示词（给 Win11 上的 DSH）

DSH 会话的工作目录设成 `O:\NaHook`。第一次开工，把下面第 1 段原样粘贴进去；之后每个任务用第 2 段；收到审计修复要求时用第 3 段。

## 1. 第一次开工（只做 T1）

```text
你是 NaHook 项目的 Go 开发者，在 Win11 上工作。仓库是 O:\NaHook（GitHub ARYYDS/NaHook，公开仓库，所以不要往里写任何密钥、令牌或服务器密码）。

第一步：完整阅读 docs/任务书-DSH.md，再按任务书 §2 的顺序全文阅读 SPEC。SPEC 是工程文档：和你自己的判断冲突时以 SPEC 为准；SPEC 没写清楚的地方，停下来问，不要自己补设计。

第二步：按任务书 §1.3 设置环境，跑一遍 §1.4 的自检，把每一项的结果贴出来。有任何一项不符合就停下。

第三步：本轮只做 T1（仓库骨架和 config 包），完成判据见 spec/01-nahook/tasks.md 的 T1。按任务书 §4 的工作循环执行。做完后按任务书 §7 的模板写交付回报，然后停下，等我的下一条指令。

硬性约束：
- 只用 Go 标准库。go.mod 写 module github.com/ARYYDS/NaHook 和 go 1.26，不出现 require。
- 只在 O:\NaHook 和 O:\WinCache 下面读写。不访问 LT，不 ssh/scp 到任何服务器，不 curl 生产地址。
- 不修改 spec/ 和 docs/reference/。
- git 只 add 具体文件，禁止 git add . 和 git add -A，禁止 force push。在 dev 分支上提交并 push；dev 不存在时用 git switch -c dev origin/main 新建。仓库平时只保留 main，合并后架构侧会删掉 dev。
- 门禁按 spec/01-nahook/audit.md §3 原样执行，回报里贴实际输出，不要概括成"通过了"。
- 你在 pwsh 7 里：环境变量用 $env:NAME，不要写 export、反引号命令替换这类 bash 语法；确实需要 Git Bash 时，显式调用 'C:\Program Files\Git\bin\bash.exe' -lc '...'。
- 命令只要可能超过 10 分钟，就把输出写到 O:\WinCache\logs\nahook-<任务>.log 再去读，不要干等。
```

## 2. 下一个任务

```text
T{上一个编号} 已收到。继续做 T{编号}，完成判据见 spec/01-nahook/tasks.md 的 T{编号}，最容易出错的地方见 docs/任务书-DSH.md §6。规则和第一次开工时一样：开工前先 git fetch --prune origin，按任务书 §4 第 1 步准备 dev（远端没有 dev 时，用 git switch -C dev origin/main 从最新的 main 新建），再 git merge --no-edit origin/main（把架构侧的 SPEC 更新和审计修复合进来），然后跑 §1.4 自检；只做 T{编号}；门禁全部通过后提交并 push dev；按 §7 的模板交付回报，然后停下。
```

## 3. 审计修复

```text
审计对 T{编号} 提出了以下问题（原文附后）。只修这些问题，不顺手改别的。每个问题对应改了哪个文件的哪几行，在回报里逐条说明；门禁全部重跑并贴输出；提交信息写 T{编号}-fix: <一句话>。做完停下。

<审计报告原文>
```
