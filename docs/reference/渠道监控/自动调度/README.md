## 结论

1. 想按普通用户切到指定渠道、并按新渠道计费，只能用"每条备用渠道一个专属别名模型"（[04](04-alias-billing.md)）。NewAPI 不允许普通用户指定渠道，也不按渠道计费。
2. 原生探测只能说明渠道是通的，测不出 TPM 余量（[02](02-admin-api.md)）。所以"故障率过高就摘除、再探测下一个"这一环必不可少（[03](03-switch-algorithm.md)）。
3. LT 上用户自己的 TPM 预测不了 429（[07](07-lt-measurements.md)），切换的主触发要用拦截事件。
4. 出厂的 Codex 亲和规则是严格模式：h3 的 `4→4` 对真实 Codex 会话不起作用；以 `gpt-` 开头的别名会被直接回 503（[01](01-newapi-native.md)）。
